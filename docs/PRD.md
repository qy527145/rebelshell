需求说明书：轻量级反向远程管理与文件传输系统（Rust + Web）


1. 项目背景与痛点

• 网络限制： 管理员电脑与虚拟机处于不同网段，中间路由器拦截了所有入站连接（管理员 \(\rightarrow \) 虚拟机）。
• 唯一通道： 该内网限制是单向的，所有虚拟机均允许主动向外建立 TCP 连接（出站不受限）。
• 核心目标： 开发一套“反向连接”的管理程序。管理端监听固定端口，虚拟机客户端主动连接并维持长连接。管理员通过 Web 界面统一对所有内网机器进行命令执行与文件管理。

2. 系统整体架构

系统采用 服务端（Server / 管理端） - 客户端（Client / 虚拟机端） 架构：
[ 虚拟机 / 客户端 ] -- (主动出站 TCP:9000) --> [ 管理员机器 / Rust 管理端 ]
 (执行命令/读写文件)                                    | (TOKEN 鉴权 + 网页端)
                                                [ Web 浏览器界面 ]

3. 详细功能需求


3.1 管理端 (Server) — 技术栈：Rust

基于 tokio 异步运行时处理高并发 TCP，使用 axum 或 actix-web 提供 Web 服务。
• TCP 监听服务： 开放一个固定的控制端口（如 9000），接收并维持所有虚拟机的反向 TCP 长连接及心跳。
• 全局密码认证 (Web端)：
	• 管理端启动时，通过配置文件或环境变量加载全局管理令牌 ADMIN_TOKEN。
	• Web 前端采用react框架，必须提供管理员令牌后才能访问。未认证的用户无法调用任何接口或连接 WebSocket。
• 可视化设备列表： 提供一个内存维护的在线设备列表（包含 UUID、主机名、IP、系统类型、最后心跳时间），并在网页端实时刷新。
• 反向命令下发：
	• 管理员在网页上选择某台机器，输入命令并提交。
	• 后端通过对应的 TCP 通道将命令发送给客户端，并在收到回显后通过 WebSocket 实时呈现在网页上。
• 文件管理支持：
	• 文件下载（发送至虚拟机）： 支持在网页端上传文件，将其转化为数据流通过 TCP 发送给指定客户端。
	• 文件上传（从虚拟机提取）： 支持输入虚拟机上的绝对路径，向客户端发送读取指令，接收返回的数据流并在浏览器端触发下载。

3.2 客户端 (Client) — 技术栈：极简设计（支持跨语言快速实现）

保持极简逻辑，不启动交互式 Shell 进程，只做“接收、执行、返回”的循环。
• 多系统命令执行兼容：
	• Linux / macOS： 收到命令后，在本地调用 sh -c "指令" 执行。
	• Windows： 收到命令后，在本地调用 powershell.exe -NoProfile -Command "指令" 执行，以支持丰富的 Windows 运维命令。
	• 无论什么系统，都必须捕获命令的标准输出 (stdout)和标准错误 (stderr)。
• 文件操作响应：
	• 收到文件写入指令时，解析文件名与数据，在指定目录创建并写入文件。
	• 收到文件读取指令时，读取本地指定路径的文件，将其转化为数据流通过 TCP 发回管理端。
• 连接保活： 每隔固定的时间（如 10 秒）向管理端发送一个 PING 包，防止连接被中间路由器防火墙因超时中断。

4. 推荐通信协议设计（供 Agent 实现参考）

为了兼顾“客户端实现足够简单”与“文件传输不阻塞命令/心跳”，建议 Agent 采用以下基于行/带长度前缀的极简文本协议：
• 基础交互（以 \n 分隔）：
	• 客户端注册：REGISTER:<UUID>:<HOSTNAME>:<OS_TYPE>\n
	• 心跳保活：客户端发 PING\n \(\rightarrow \) 服务端回 PONG\n
• 命令交互（对执行结果进行 Base64 编码，防止因换行符导致粘包）：
	• 下发命令：CMD:<命令字符串>\n
	• 回显结果：RESULT:<Base64编码后的执行结果>\n
• 文件交互（大文件建议采用分块 Chunk 机制，避免阻塞心跳）：
	• 发送文件到虚拟机：SEND_FILE:<文件名>:<文件大小(bytes)>:<Base64数据数据或分块标识>\n
	• 从虚拟机提取文件：GET_FILE:<远程绝对路径>\n
	• 虚拟机返回文件数据：FILE_DATA:<文件大小(bytes)>:<Base64数据>\n
